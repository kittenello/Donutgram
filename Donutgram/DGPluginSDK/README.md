# donutgram plugin sdk

start with the plugin documentation at [docs.forktg.surf](https://docs.forktg.surf), also linked from the about screen. types, strict schemas, examples and local tooling are in this directory. native installer, broker and runtime remain authoritative.

`tools/dgplugin.py validate-ui page.json` checks native page structure, UTF16 limits and relational numeric/select constraints beyond portable JSON Schema. `test <example> <fixture>` checks reviewed pure example logic with passive native/network fixtures; it is not an iOS or sandbox test.

settings schema fields stay editable while a plugin is disabled. opening a custom settings page starts a temporary local settings session: `api.environment.get()` reports `executionMode: "settings"`. register settings commands in `activate()` before doing work that requires normal execution. this session can use local storage, settings, packaged images and its own native UI as far as the plugin would hold them if it were turned on now: its required permissions and the optional ones the user granted, never a declined optional one. it cannot access chats, send messages or make network requests. chat commands, transforms and event subscriptions remain inactive. it does not enable the plugin or persist extra permission grants, and stops when its settings screen closes. like every runtime it also stops while the app is in the background or in power saving; while the screen is still open, a new session starts when the app returns, so register settings commands on every activation and render pages again from a command.
