# portable production verification

`powershell -ExecutionPolicy Bypass -File Donutgram/DGPluginTests/Portable/run-tests.ps1` builds the actual model, installer, quickjs runtime, public-network helpers and host as windows libraries, then executes the production XCTest scenario methods through a small standalone assertion/expectation adapter. no installer/runtime/manager implementation is replaced with a stub. fake native screen adapters remain only where a test deliberately delays or rejects an external UI operation.

the script requires an existing swift6.4.2 windows toolchain/sdk/runtime and the local visual studio clang toolchain; paths are parameters. it does not install system software or modify user PATH permanently. sources and outputs stay in repository and temporary build directories. host compilation uses `DG_PLUGIN_TESTS` with a fresh `DG_PLUGIN_TEST_ROOT`; account/package records never use the user's normal plugin store. the flag changes only the storage root; permission, scope, generation and runtime checks remain production code.

the production installer uses CryptoKit SHA256/Ed25519 and ImageIO on Apple platforms. on windows it uses the native BCrypt SHA256 primitive through the same archive C bridge. known empty/abc vectors are tested. when CryptoKit is unavailable, a signed package fails explicitly with `feature_unavailable`; it is never downgraded to an unsigned package. when ImageIO is unavailable optional icons fall back to a monogram. those platform guards enable actual parser/zip/storage/broker/runtime verification without claiming Windows verifies Apple signature/image behaviour.

the portable zlib build uses official zlib1.3.2 source solely in the temporary test toolchain: `https://github.com/madler/zlib/releases/download/v1.3.2/zlib-1.3.2.tar.gz`, sha256 `bb329a0a2cd0274d05519d61c667c062e06990d72e125ee2dfa8de64f0119d16`, checked before extraction. this checksum was obtained from the upstream release API asset digest. Apple production continues to link the platform zlib; the test toolchain does not add a new application dependency. C/C++ objects use the dynamic MSVC runtime when linked into Swift libraries.

executed scenarios include native SHA vectors; side-effect-free metadata parsing; immutable package bytes; duplicate/computed/getter/spread metadata; forbidden capabilities/profiles; compatibility and archive bounds; valid raw-deflate extraction; zip traversal/symlink/collision/CRC/expansion/count/nesting rejection; real broker denial of undeclared storage and forged identity/methods; exact slot confinement; installation-local storage; bounded deep storage; grant/settings rejection; profile-changing update rejection; cancellation of an outstanding native read after disabling. supplementary real helpers cover semantic-version ordering without integer overflow and immutable native confirmation tokens: scope/recipient matching, single use, expiry, paid-recipient denial, cancellation and scoped removal.

the original Apple XCTest targets remain available. the standalone runner tests the same scenario method bodies, not Apple's XCTest integration. Network/Security transport, CryptoKit/Ed25519 interoperability, ImageIO, UIKit rendering, actual engine-to-screen integration, fault injection and simulator video/frame checks still require their own Apple-host validation. a successful windows run is evidence for the production paths it executes, not a complete iOS build or product acceptance claim.
