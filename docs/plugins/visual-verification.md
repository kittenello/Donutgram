## intended frames, before recording

the plugins row appears in the extensions group and reflects the running count or global stop. the grouped plugin list shows search only with at least five installed plugins and contains the global switch and compact cards separated by 10 pt. each card has a 44 pt square icon, name, author/version/state, an inline switch, a short description and three labelled actions: settings, share and remove. there is no overflow menu or separate enable row. tapping a title or picture opens details; toggling only changes enablement. returning keeps the list position. with no plugins, keep the installed section header and leave its content empty without an installation hint. when the installed count falls below five, hide search and clear its query so the remaining cards are visible. an active search with no matches still shows the no-results message. long names and descriptions wrap within their measured limits; the full title remains accessible. dark and light themes keep readable contrast. verify at 320, 390 and 430 pt and with the largest list font.

opening a telegram plugin document keeps the chat visible behind a compact native loading overlay. tapping the overlay cancels; a cancelled import must never open a late card. successful validation opens a bottom sheet above the dimmed chat. the whole sheet moves upward on one 250 ms ease-out without overshoot; its icon, name, metadata, description, switch and primary button move together. closing reverses it in 200 ms without a gap or colour flash. reduced motion disables the translation. the sheet is capped at 480 pt wide and scrolls when content cannot fit above safe areas. its 68 pt square icon is followed by the name, author/version and description; trust, digest, package id and permission tables are absent. a download or validation failure still dismisses loading and presents an alert within the 30-second deadline. no import or review step executes javascript. the enable-after-install switch starts on when plugins are globally enabled; while globally paused it is off and disabled; turning it off stores the plugin without granting or running it. installation plus activation uses the reviewed digest. repeated taps cannot install twice. opening an already installed or older file offers settings instead of trying to reinstall it. activation errors remain visible in the sheet with settings available for the installed package.

the document preview icon changes only after a completed telegram resource passes static validation. plugin icons use the same compact 44 pt file layout with or without bubbles, including grouped documents. loading the icon must not increase the row height or move the filename. non-square artwork is fitted into a square canvas without stretching. no external icon url is loaded and no javascript runs. malformed plugin files retain the ordinary document icon. a missing or broken optional icon uses a puzzle symbol, never initials. resource parsing and image decoding run off the chat layout queue. cached icons are keyed by package digest, so an update cannot retain the previous image by id alone.

enabling, disabling, granting/revoking rights, account switching, global stopping, failure and quarantine must update the list and details consistently. while globally paused, individual enable switches in the list, details and install sheet are disabled; settings, sharing and deletion remain available. saved individual states survive pause and resume. the global switch has no pause subtitle or running count, and plugin rows do not repeat the global pause status. no row reports running before activation succeeds. a stale rendered page cannot invoke callbacks after stop or permission revocation.

the removal confirmation names the plugin and explains that all of its accounts' local data on this device is removed. cancelling changes nothing. successful confirmed removal returns to the original updated list controller and shows a short removal notice; installation cards opened directly from a document become the list when no earlier list exists. cancelling does not stop the runtime. resetting data has its own confirmation and applies only to the current account.

sharing from a card or details opens the native Telegram recipient picker, with no system activity sheet. verify saved messages, another chat, multiple recipients and forum topics. cancelling must enqueue nothing. the sent document retains the exported filename, extension, exact package bytes and size; it remains available to the uploader after closing the plugin page. repeat with global plugin execution disabled. cache preparation failures show an error without opening the picker.

## implemented renderer subset

section, text, markdown, list, button, toggle, input, multiline, select, slider, stepper and image use the same native grouped-list renderer. page payloads are limited to 64 kib, 128 nodes and depth 6; ids are unique; unknown fields, invalid callback placement and control/bidirectional title characters are rejected. select options use `{title, value}` with scalar json values including null. numeric controls require finite minimum/maximum/step and an aligned value; sliders normalize to 0…1 to retain useful precision at large offsets. image nodes accept only opaque host-issued local raster handles, with no url or package-path loader and at most eight decoded images per page. markdown is a bounded plain parser for headings, lists, emphasis and code; link destinations are discarded and html stays literal text. runtime-bound validity is checked immediately before each callback. host cleanup closes the page after stop/revoke. repeated rendering of the same page replaces its content in the same controller; superseded and closed page states cannot dispatch callbacks. native row callbacks also require the current page revision.

composer commands appear in the chat avatar menu; explicit chosen-message commands appear in the message menu. draft snapshots use opaque owner-bound handles and revisions, expire after 30 seconds and are single-use for edits. edits compare the complete original `ChatTextInputState` immediately before the existing undo-aware update closure and use `replacingFlatRange`. the snapshot exports plain text only and reports incomplete entities/structure. ordinary-message preparation and send adapters are owned and verified separately from this ui work. protected/service messages are excluded independently of user bypass settings.
