# public network adapter

`DGPluginPublicNetwork.request(params:allowedOrigins:validity:completion:)` returns a cancellation closure. the host supplies exact granted origins and a generation/account/permission validity closure. the host must retain cancellation as a runtime-owned resource and invoke it on permission revocation, account change, disable and removal. one completion is produced, including cancellation. host-side quotas bound request rate and concurrent requests; this adapter bounds each request and never takes identity, origins or grants from javascript. `isAvailable` reports whether the native Apple transport exists on the build platform.

the request schema is exactly `{url: string, method?: "GET" | "HEAD"}`. extra fields, headers, bodies, credentials, fragments, non-default ports, noncanonical hosts and nongranted origins fail. only ascii dns names over https are accepted. the wire request has a fixed user agent, accept/identity encoding and connection-close headers. it has no cookie jar, telegram transport, account headers, cache, client certificate, user session or proxy credentials. public-network profile separation is enforced independently by the host before this adapter is called.

dns resolves on a worker. every answer must pass the address filter; mixed public/private answers fail. the connection is made to one already checked numeric endpoint, so Network does not re-resolve the hostname between validation and connect. TLS sends the original hostname as SNI and explicitly verifies the certificate against that hostname using system SSL trust. certificate network fetching is disabled to prevent AIA/revocation fetches becoming unvalidated secondary destinations. TLS is at least1.2; ALPN requests HTTP/1.1. no insecure verification callback or custom trusted certificate is installed.

the address policy is intentionally conservative: ordinary public ipv4 and globally allocated ipv6 in2000::/3 are allowed, while special-purpose, private, loopback, link-local, mapped, translation/tunnel, multicast and documentation ranges are denied. some globally reachable special-purpose assignments are also denied. scopes, alternate numeric notations and ipv4 leading-zero spellings fail. future special-purpose assignments require updating this policy. DNS64/NAT64-only destinations are currently unsupported rather than allowing synthesized addresses that may conceal a forbidden ipv4 endpoint.

responses are passive utf8 data `{url,status,headers,body}`. no content is evaluated or loaded as a javascript module. only content-type, etag, last-modified and cache-control response headers are returned; cookies and authentication headers are omitted. redirects, informational/upgrade responses, compressed bodies, ambiguous/duplicate headers, trailers and chunk extensions fail explicitly. the strict HTTP/1 subset supports content-length, bounded chunks and connection-close bodies. this deliberately sacrifices compatibility with servers that rely on excluded forms.

limits:10seconds monotonic overall deadline,16KiB headers/64headerfields,48KiB body,96KiB total wire buffer,1024chunks,60KiB json-encoded reply. escaping overhead can therefore reject a body below48KiB. cancellation closes the connection and suppresses further processing. a blocked system dns resolver may retain its worker until the OS returns, but the deadline/cancellation completion and UI do not wait for that worker. DNS answer strings and response bodies are never logged.

verification: six pure request/address/HTTP test groups were compiled and executed against actual production helper/model libraries with swift6.4.2 on windows; all passed. tests cover origin confusion, forbidden addresses and numeric forms, request injection, response framing, every incremental prefix of a chunked response, redirects, header ambiguity, compression, truncation and reply quotas. `powershell -File Donutgram/DGPluginNetwork/run-tests.ps1` reproduces that run using a small assertion adapter for the same XCTest scenarios, since this windows toolchain has no XCTest module. the transport's non-Apple unavailable fallback also passed type checking. the native Network/Security connection path still requires an Apple-host compile plus actual TLS-hostname, mixed-DNS, cancellation and timeout integration tests before release; windows helper checks do not verify Apple networking.

references reviewed2026-11-08: [Apple TLS server name](https://developer.apple.com/documentation/security/sec_protocol_options_set_tls_server_name(_:_:)), [Apple TLS verification](https://developer.apple.com/documentation/security/sec_protocol_options_set_verify_block(_:_:_:)), [Apple trust policy](https://developer.apple.com/documentation/security/sectrustsetpolicies(_:_:)), [IANA ipv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry), [IANA ipv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry). system routing can direct a nominally public address into a private administrative network; numeric classification cannot prove the topology of every VPN or enterprise route. the adapter does not claim such a guarantee.
