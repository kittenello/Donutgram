# threat model

the attacker controls attachment bytes, source modules, manifest strings, resources, javascript execution and every bridge parameter. different plugins, publishers, accounts and installation generations are distinct principals. a signature only binds content to possession of an ed25519 key. an unsigned author name or username has no identity authority.

preview is a pure bounded parser and image sanitizer. it neither evaluates javascript nor fetches urls. verified packages own copied input bytes, content digests and immutable file dictionaries. installer and runtime limits agree: 8 mib attachment, 4 mib expanded files, 128 entries and 1 mib/file. file paths are ascii package-relative components. archive metadata cannot create operating-system links because extraction only produces data values. bad optional icons become placeholders; image decoding still shares the app process and remains a native attack surface.

each plugin/account uses a separate quickjs runtime. heap, stack, source, queue and pending-job limits bound known abuse. an atomic stop latch reaches engine interrupt polls during execution. the interpreter runs in the app process; queue separation does not protect against an interpreter memory-corruption bug. some native builtins can run until a later poll, so a strict preemptive wall deadline is not established merely by the ordinary loop fixtures. arbitrary programs can implement interpreters for data; deleting eval does not prove that downloaded data can never influence behaviour. the initial generic network adapter remains unavailable.

the native broker binds installation/account/generation outside javascript and checks an explicit method rule, declarations, exact grants, scope, gesture and quota before delivery. forbidden authorization, session, payment, gift, moderation, destructive-history and raw-native operations have no method rule. plugin storage and settings cannot alter those rules. cached snapshots are data, not references to swift objects.

private-data and public-network profiles are mutually exclusive. this applies across versions: a profile-changing update must not inherit historical private storage or settings. v1 rejects the profile change and requires removal with data cleanup before a fresh installation. independent plugins have no shared storage or ipc. external urls, clipboard, share, notifications, exports and interactive sends are unavailable until their native policies are implemented; a missing fetch alone would not close those channels. sensitive service/auth content must be excluded by screen adapters before creating snapshots.

revocation invalidates generations and stops execution. native asynchronous effects must call the supplied validity check immediately before committing. checking only after a side effect is too late. late read results are rejected before javascript receives them. durable removal prevents restart activation and device-wide removal clears every account record. disk errors must not keep a runtime executing after the user requests stop.

remaining threats include interpreter/image-decoder defects, malicious social engineering, user-entered secrets in a plugin's own settings, intentional manual disclosure, and code with logic not detectable by static metadata parsing. the client must visibly identify plugin ownership in native ui. signatures and a developer channel cannot disable broker policy. app-store execution is compiled out until distribution compliance is established.

verification layers are separate: bounded parser tests; real engine hostile fixtures; real policy/manager negative tests; full ios build; recorded simulator frames; device pacing. a pass in one layer is not evidence for another. see security-review.md for observed checks and unresolved limitations.
